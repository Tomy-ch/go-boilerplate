# Question

問い手の意図を解釈し、本当に曖昧な点だけを確認して、答えを所有するスキルへ問いを引き渡す。
ここでは決して問いに答えない。

英語版 `SKILL.md` が正本であり、この文書は人間向けの参考訳である（スキルとしては読み込まれない）。

## いつ使うか

このスキルは次の場合に使う。

- 問いに 2 通り以上の合理的な読み方がある。
- 問い手がどのスキルが対象を所有するか分からない、または問いをどこへ渡すべきか尋ねている。
- 前の実行が別の読み方に答えてしまい、問いを振り直す必要がある。
- 「今」「どうなの」「大丈夫」のような範囲を示さない表現により、世界・意図・対象が定まらない。

読み方がすでに一意なら使わず、所有スキルを直接起動する。このスキルで答え、手順、比較、レビューを
作ってはならない。

## 契約

| | |
| --- | --- |
| **所有するもの** | 問いの意味論的解釈（世界 / 意図 / 対象の 3 軸）、人間への確認、所有スキルへの引き渡し |
| **決してしないこと** | 自分で答える / 手順を組む / 比較する / レビューする / 軸が割れているのに黙って片方を選ぶ |
| **開始条件** | 問いの読み方が一意でないとき、どのスキルが担当か分からないとき |
| **停止条件** | 引き渡し先が決まったとき、または該当するスキルが無いと分かったとき |

## このスキルが存在する理由

別のスキルは、明らかに誤った入口へ来た問いを拒否できる。しかし、複数の読み方のどれでも成立する
問いはそれでは解決しない。異なる所有者がそれぞれ自信を持って有能かつ別の範囲の答えを出せてしまい、
その答え自体からは別の読み方があったと分からないためである。

裸の「今」が典型例である。これはリポジトリ外の一般的なやり方、現在のリポジトリ全体、またはこの窓の
変更を指しうる。曖昧さはファイルではなく問い手の意図にある。したがって問い手が解決する。確認は弱い
ヒューリスティックの代替ではなく、正しい情報源への照会である。

## 3 つの軸

問いを以下の独立した軸で解く。ほとんどの問いは 3 軸すべてを定めている。このスキルに届く問いは通常
1 軸、まれに 2 軸で割れる。

| 軸 | 読み方 | 割れている合図 |
| --- | --- | --- |
| **世界** | 外の世界 / このリポジトリ全体 / この窓の差分 | 裸の「今」「最近」「普通」、または基準を示さない比較 |
| **意図** | 症状 / 目標 / 知識 / 未決の選択 | 行動や失敗を示す動詞がない「どう」「大丈夫」「どうなってる」 |
| **対象** | 実装 / テスト / コメント / ドキュメント / 語彙 / 運用 | 複数の対象を包む「品質」「これ」「この機能」 |

スキル名を挙げる前に、解けた各軸を問い手自身の問いの読み方として述べる。問い手はツール一覧を知らなく
ても「差分ではなくリポジトリ全体の話」と訂正できる。スキル名から選ばせるのは、その知識があると誤って
仮定することになる。

## ステップ 1 — 問いがすでに述べていることを解く

問いを 1 行で言い換え、文面または直前の文脈が実際に定めている各軸の読み方を示す。意図を明確にする
ために実装や文書を調べてはならない。それは引き渡し先の仕事を行うことであり、問い手の意図も明らかに
できない。

次の 2 つの文脈上の合図は正当に軸を確定できる。使った場合は必ず明示する。

- **現在の差分状態。** ブランチの未マージコミットがあれば「この窓」の読みが妥当になり、クリーンな
  ツリーなら可能性は低い。Git の状態だけを確認し、分かったことを述べる。
- **直前の会話。** レビューの直後に来た問いは、通常その変更を指す。問い手が訂正できるよう、会話の
  文脈からの推論だと明示する。

## ステップ 2 — 割れている軸だけを確認する

すべての軸が解けた場合、1 行で読み方を示した後、確認せずステップ 3 へ進む。一意な問いに摩擦を
加えてはならない。

本当に割れている各軸について、対話本文に番号付き選択肢を示し、ユーザーの返答を待つ。1 ターンで尋ねる
短い質問は 2 つまでとする。各選択肢はスキル名ではなくユーザーの問いの読み方として書き、必ず
「どれでもない」を含める。例:

```text
「今」はどの範囲を指していますか？

1. 外の世界と比べて — 一般的なやり方として今も妥当か
2. このリポジトリ全体 — コードベース全体が筋の通った状態か
3. この窓の変更 — いま書いた差分がどうか
4. どれでもない — 別の意味だった
```

ルーター自身が考えた候補だけを示すと、どれも正しくない場合でもその 1 つを回収してしまう。
「どれでもない」はこの誤った解決を防ぐ。

## ステップ 3 — 実行時に引き渡し先を見つける

ルーティング表を決して焼き込まない。インストール済みの Codex スキルを列挙し、その英語正本の
frontmatter を読む。

```bash
find .codex/skills -mindepth 2 -maxdepth 2 -name SKILL.md -print
sed -n '1,/^---$/p' .codex/skills/<candidate>/SKILL.md
```

各 `description` を所有境界の第一の根拠とする。末尾の「Do NOT use…」節は、所有者自身がその境界を
書いたため特に信頼できる。判断が拮抗する場合は、候補に `## Contract` 表があれば読む。ルーティング
前に引き渡し先が存在することを確認する。

同期の途中では Codex のスキルツリーが一時的に Claude 側より遅れている可能性がある。現在
インストールされている `.codex/skills/` の英語正本だけを根拠にし、Claude 側のスキルがここでも使えると
仮定してはならない。解決した問いを所有する Codex スキルがなければ、一覧の不足として報告して停止する。
所有者がないことは、このルーターが答えてよい理由にはならない。

元の問い、解決した 3 軸の読み方、その読み方が決める引き渡し先の引数を渡す。引数は引き渡し先の現在の
`SKILL.md` から導出し、別環境または以前の版で記憶したフラグを引き継いではならない。

## ステップ 4 — 引き渡す

解決した読み方、引き渡し先、所有理由を日本語 1 行で述べ、そのインストール済みスキルを起動する。
ユーザーが読み方を確認した後に、二度目の確認を求めてはならない。

```text
「この窓の変更について、テストを評価したい」という読みで受け取りました。この問いを所有する /<skill> に引き渡します。
```

この 1 行の引き渡しだけが、このスキルの所有する出力である。答えを先取りしたり、引き渡し先が見つけそうな
ことを要約したり、未解決の読み方を網羅するために複数の引き渡し先を起動したりしてはならない。

## 引数

| 引数 | 効果 |
| --- | --- |
| `[question]` | 3 軸の手順でこの問いをルーティングする |
| `--to=<skill>` | 呼び出し側が引き渡し先を知っている。インストール済みか確認し、軸の解決を飛ばして引き渡す |
| `--explain` | 軸の解決、引き渡し先、所有理由を示し、起動せずに停止する |

ユーザーが問いの行き先を尋ねた場合、またはルーティング判断を検査したい場合は `--explain` を使う。

## チェーンではない

このスキルは、解決した 1 つの読み方を、独立して起動できる 1 つの所有者へルーティングする。複数の答えを
集めるパイプラインではない。本当に割れている読み方は人間が所有し、その判断後にルーターは 1 度だけ実行
する。明確に範囲が定まった問いは、このスキルを通す必要がない。

## すること / しないこと

- ✅ 文面と直前の文脈が定める軸をすべて解く。
- ✅ 本当に割れている軸だけを確認する。
- ✅ 番号付き選択肢をスキル名ではなく問いの読み方として書く。
- ✅ 確認の選択肢に必ず「どれでもない」を含める。
- ✅ 実行時に `.codex/skills/*/SKILL.md` の frontmatter からインストール済みの所有者を探す。
- ✅ 元の問いとともに、解決した読み方と現在の引き渡し先の引数を渡す。
- ✅ Git の差分状態または直前の会話が軸を確定した場合は明示する。
- ✅ 所有者のない問いを一覧の不足として報告し、停止する。
- ✅ ユーザーに見えるすべての文を日本語で出力する。
- ❌ 問いに答える、手順を作る、選択肢を比較する、またはレビューする。
- ❌ 軸が割れているときに読み方を黙って選ぶ。
- ❌ ルーティング表を焼き込む、または未インストールのスキルへ引き渡す。
- ❌ 問い手の意図を推測するためにコードベースを読む。
- ❌ 読み方がすでに一意な問いについて確認する。
- ❌ 1 つの未解決な問いに複数の引き渡し先を起動する。
