# job コマンド

## 役割

`job` コマンドは、アプリケーション内で定義されたジョブを CLI から実行するためのユーティリティです。ジョブ名と引数を受け取り、DI レイヤーのジョブ実行ロジックを呼び出して同期的に実行結果を待ちます。

## 実装の要点

- コマンド定義: `internal/cli/job/job.go` の `NewCommand()` で `job` コマンドを生成します。最小引数は 1（ジョブ名）。
- ジョブ実行: `runJobExec` が実行の本体で、DI レイヤーの `di.RunJob()` を呼び出して `start(ctx, name, args)` を実行します。
- タイムアウト: `--timeout` フラグでジョブ実行のタイムアウトを指定できます（`time.Duration`）。タイムアウトが設定されると、指定時間でキャンセルされます。
- 停止処理: ジョブは `start` が返す `done` チャネルで終了を通知します。完了後、`stop(context.Background())` を呼んでクリーンアップします。タイムアウトや呼び出し元コンテキストのキャンセル時も `stop` が呼ばれます。

## 使い方

基本的な実行形式:

```sh
job <job-name> [args...] [--timeout DURATION]
```

フラグ:

- `--timeout`: ジョブの実行タイムアウト（例: `30s`, `1m`）。未指定だと無制限。

### 実行例

- ローカルでバイナリを使う例:

```sh
./your-app job usercount --timeout 30s
```

- `go run` で実行する例（開発）:

```sh
go run ./cmd/main.go job usercount --timeout 30s
```

## 前提 / 要件

- `di.RunJob()` が正しく実装され、指定するジョブ名に対応するジョブが登録されていること。
- ジョブ実行に必要な依存（DB 接続や外部リソース等）が DI を通じて解決できること。
- 長時間実行のジョブを扱う場合は `--timeout` を適切に設定するか、呼び出し元のコンテキスト管理を行ってください。

## 注意点

- ジョブ実行は同期的に `done` チャネルの完了を待ち、完了後に `stop` を呼び出します。`stop` の実行により後始末が行われますが、`stop` 自体の失敗はログに出力される可能性があるため、実装側でエラーハンドリングを行ってください。
- タイムアウトやキャンセルが発生した場合、`stop` は必ず呼ばれますが、ジョブ内部の中断可能性はジョブ実装に依存します（協調的なキャンセルが必要）。
- 引数のパースやバリデーションは各ジョブ実装側で行うことを想定しています。

## トラブルシューティング

- ジョブが見つからない/未登録: `di.RunJob()` にジョブが登録されているか確認してください。
- ジョブがタイムアウトする: `--timeout` を延長するか、ジョブ実装で中断処理を改善してください。
- キャンセルやコンテキスト関連のエラー: 呼び出し元のコンテキスト管理（外側でキャンセルが発生していないか）を確認してください。

## 拡張・カスタマイズ

- `--timeout` のデフォルトを設定したい場合は、`NewCommand` でデフォルト値を設定できます。
- ジョブ実行の前後で追加のロギングやメトリクスを挟みたい場合は `runJobExec` をラップして処理を差し込んでください。
- `stop` の呼び出しを非同期化したり、リトライを追加するなど、終了/後処理の戦略は `di` 側と協調して拡張してください。
