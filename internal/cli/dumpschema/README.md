# dump-schema コマンド

概要: `dump-schema` コマンドは外部のデータベースダンプツール（デフォルト: `pg_dump`）を実行してスキーマのみをダンプし、
出力からダンプツール固有のメタコマンド行（例: psql の `\` で始まる行）を除去して `sqlc` で読み込みやすい形式に整形するユーティリティです。

## 役割

- DB に接続してスキーマを取得し、リポジトリ内の `database/gen/schema.gen.sql`（デフォルトパス）へ保存・整形します。

## 主要挙動（実装の要点）

- 使用コマンド: デフォルトは `pg_dump` に設定されていますが、`dumpCommand` を差し替えることで任意のダンプツールを利用できます（ソース内の `dumpCommand` 変数）。
- 引数: デフォルトのサブ引数は `--schema-only --no-owner --no-privileges --format=plain`（`dumpSubArgs`）ですが、`dumpArgs` に差し替えることで変更可能です。
- 出力先: ジェネレーターの `workDir` と `schemaRelPath` により決まり、実装デフォルトは `/app` と `database/gen/schema.gen.sql`。
- サニタイズ: 出力ファイルの各行を走査し、先頭がバックスラッシュ（例えば psql のメタコマンド）で始まる行など、ダンプツール由来の不要なメタ行を除去して上書き保存します。
- ファイルパーミッション: 出力ファイルは `0o644`（rw-r--r--）で書き込みます。
- ロギング: 実行開始/完了/警告はアプリケーションのロガーへ出力します。

## 前提 / 注意点

- ダンプコマンド（デフォルト: `pg_dump`）が PATH に存在し、実行環境（ローカルまたはコンテナ）から DB に接続できること。
- コマンドはアプリケーションの設定から取得する DSN（`config.NewDatabaseConfig(cfg).DSN()`）を最初の引数として渡します。設定が正しく読み込まれていることを確認してください。
- `workDir` が `/app` に固定されているため、ローカルで実行する際はワークディレクトリを適切に設定するか、コードの `workDir` フィールドを調整してください（コンテナ内での利用を想定した値です）。
- psql のメタコマンドのみを除去する簡易整形を行います。より高度な整形やフィルタリングが必要な場合は `sanitizeSchemaInPlace` を拡張してください。

## 多DB対応について

- デフォルトでは `pg_dump` を使う設定ですが、実装は `dumpCommand` と `dumpArgs`（ソースでは `dumpSubArgs` を `dumpArgs` に割り当て）を差し替えるだけで他のデータベースにも適用可能です。

### 変更すべきポイント

例: MySQL に対応させる場合は、`dumpCommand = "mysqldump"`、`dumpArgs = []string{"--no-data","--skip-comments"}` のようにし、`sanitizeSchemaInPlace` を MySQL の出力に合わせて調整します。

下記方針により、コード本体を大きく変更せずに複数の DB 環境で再利用できます。

#### ダンプコマンド

`dumpCommand` を対象 DB のダンプツール（例: `mysqldump`, `sqlite3` など）に変更します。

#### 引数

`dumpArgs` を対象 DB のスキーマ出力に適したフラグへ置き換えます（例: MySQL では `--no-data` や `--skip-comments` など）。

#### サニタイズ処理

`sanitizeSchemaInPlace` は現状 psql のバックスラッシュで始まる行を取り除く実装です。他 DB のダンプ形式ではメタ情報やコメントの形式が異なるため、必要に応じて削除ロジックを拡張または置換してください。

#### 出力パス/ワークディレクトリ

`workDir` と `schemaRelPath` を実行環境に合わせて調整してください（コンテナ内での実行を前提に `/app` が使われています）。

## 使い方の例

- アプリケーションの CLI に組み込まれている想定です。バイナリ実行時のコマンド名は `dump-schema`。
  - 例: `./your-app dump-schema`

## カスタマイズ

- `dumpCommand` と `dumpSubArgs` はソース内で変数として定義されているため、必要に応じてコマンドや引数を変更できます（例: デフォルトのダンプツールを他のツールに差し替える場合など）。
- `workDir`、`schemaRelPath`、およびファイルパーミッションは `generator` のフィールドで変更可能です。

## トラブルシューティング

- ダンプコマンドが失敗した旨の警告が出る場合、DSN の接続情報、ネットワーク、ダンプツールのバージョン互換性、あるいは実行権限を確認してください。
- 出力ファイルが空または不完全な場合は、ダンプコマンドの標準エラー出力（この実装では `os.Stderr`）を確認してください。
