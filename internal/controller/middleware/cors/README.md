# CORS Middleware

概要: このディレクトリは、CORS (Cross-Origin Resource Sharing) に関するミドルウェアを提供します。特定のオリジンからのリクエストを許可する設定を行います。

## 役割

- 特定のオリジンからのリクエストを許可し、セキュリティを確保しながらクロスオリジン通信を可能にします。
- 許可されたHTTPメソッドやヘッダーを制御します。

## 必要度

### 本番運用での必須度

- 必須度: 1
  - 1: 本番運用で必須
  - 2: 本番運用で推奨
  - 3: 開発環境でのみ必要
  - 4: テスト環境でのみ必要
  - 5: 無し

理由: 本番環境では、セキュリティを確保しつつ、特定のオリジンからのリクエストを許可するために必須です。

### 開発/テスト運用での必須度

- 必須度: 1
  - 1: 開発/テスト運用で必須
  - 2: 開発/テスト運用で推奨
  - 3: 開発/テスト運用で任意
  - 4: 無し

理由: 開発やテスト環境でも、クロスオリジン通信をテストするために必要です。

### 無効化した場合の影響

- クロスオリジン通信がブロックされ、フロントエンドとバックエンド間の通信が失敗する可能性があります。
- セキュリティ上のリスクが増大する可能性があります。

## middleware.CORSConfig の設定項目

- `AllowOrigins`: 許可するオリジンのリストを指定します。
  - 設定は、config.Configの `AllowedOrigins` フィールドから取得されます。
- `AllowMethods`: 許可するHTTPメソッドを指定します。
- `AllowHeaders`: 許可するHTTPヘッダーを指定します。
  - セキュリティ強化のため、必要なヘッダーのみを指定することが推奨されます。
- `ExposeHeaders`: クライアントに公開するレスポンスヘッダーを指定します。
  - 許可するヘッダーを明示的に指定することが推奨されます。
- `AllowCredentials`: クッキーなどの含むリクエストを許可するかどうかを指定します。
  - 原則的に、セキュリティ上の理由から `false` に設定することが推奨されます。
  - 手動で設定された`Authorization`ヘッダーは `false` 下でも許可されます。

## 注意点

- 許可するオリジンやHTTPメソッド、ヘッダーを適切に設定してください。
- 必要以上に広範囲なオリジンを許可しないように注意してください。
- 他のミドルウェアと組み合わせて使用する際、適切に動作することを確認してください。
