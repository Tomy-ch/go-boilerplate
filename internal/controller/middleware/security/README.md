# Security

概要: このディレクトリは、CSRF (Cross-Site Request Forgery) 対策を含むセキュリティ関連のミドルウェアを提供します。

## 役割

- セキュリティヘッダーを設定し、アプリケーションをさまざまな攻撃から保護します。
- CSRF攻撃やXSS攻撃、クリックジャッキングなどのリスクを軽減します。

## 必要度

### 本番運用での必須度

- 必須度: 1
  - 1: 本番運用で必須
  - 2: 本番運用で推奨
  - 3: 開発環境でのみ必要
  - 4: テスト環境でのみ必要
  - 5: 無し

理由: 本番環境では、セキュリティヘッダーを適切に設定することで、攻撃リスクを軽減できるため必須です。

### 開発/テスト運用での必須度

- 必須度: 2
  - 1: 開発/テスト運用で必須
  - 2: 開発/テスト運用で推奨
  - 3: 開発/テスト運用で任意
  - 4: 無し

理由: 開発やテスト環境でも、セキュリティ設定の動作確認を行うために推奨されます。

### 無効化した場合の影響

- セキュリティヘッダーが設定されないため、CSRF攻撃やXSS攻撃、クリックジャッキングなどのリスクが増大します。
- アプリケーションのセキュリティが低下し、攻撃に対して脆弱になります。

## middleware.SecureConfig の設定項目

- `XSSProtection`: XSS (クロスサイトスクリプティング) 攻撃を防ぐための設定。
  - 現代では、ブラウザが自動的にXSS保護を提供するため、通常は設定不要です。
- `ContentTypeNosniff`: ブラウザがMIMEタイプを推測しないようにする設定。
  - 例: `nosniff`。
- `XFrameOptions`: クリックジャッキング攻撃を防ぐための設定。
  - 例: `DENY`。
- `ReferrerPolicy`: リファラーヘッダーの送信ポリシーを設定。
  - 例: `no-referrer`。
- `HSTSMaxAge`: HSTS (HTTP Strict Transport Security) の有効期間を秒単位で指定。
  - 本番環境では有効にすることが推奨されます。
  - 例: `31536000` (1年)。
- `HSTSExcludeSubdomains`: HSTSをサブドメインに適用するかどうかを指定。
  - 本番環境では有効にすることが推奨されます。
  - 例: `true` または `false`。

## 注意点

- 本番環境では、HSTS設定を有効にすることを推奨します。
- セキュリティヘッダーの設定は、アプリケーションの要件に応じて適切にカスタマイズしてください。
- 他のミドルウェアと組み合わせて使用する際、適切に動作することを確認してください。
