# `security` パッケージ

概要: HTTP レスポンスヘッダのセキュリティ強化を行う Echo ミドルウェアを提供します。ブラウザ向けのセキュリティヘッダ（Content-Security-Policy 以外の一般的なヘッダ）を設定し、環境に応じて HSTS の挙動を調整します。

## 役割

`security` は `middleware.SecureWithConfig` に渡す設定を構築し、Echo ミドルウェアとして返します。主に以下のヘッダを設定します:

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: no-referrer`
- HSTS 設定（本番環境では有効化し、サブドメイン含めない設定）

主要ファイル:

- `security.go` : ミドルウェア生成と環境に応じた `SecureConfig` の構築。
- `security_test.go` : 挙動を検証する単体テスト。

## 必要度

### 本番運用での必須度

- 必須度: 本番運用で推奨

理由: 適切なセキュリティヘッダはクライアントサイドの攻撃（クリックジャッキング、MIME スニッフィング等）を軽減します。HSTS は HTTPS を常用する場合に重要です。

### 開発/テスト運用での必須度

- 必須度: 開発/テスト運用で推奨（ケースにより任意）

理由: 開発環境では一部ヘッダを緩和したい場合がありますが、基本的には本番に近い設定でテストすることを推奨します。

### 無効化した場合の影響

ミドルウェアを適用しない場合、ブラウザ向けのセキュリティヘッダが送出されず、クリックジャッキングや MIME スニッフィングといったリスクが高まります。HTTPS を強制する HSTS を利用している場合、設定ミスはセキュリティ上の問題を引き起こします。

## 注意点

- Content-Security-Policy（CSP）などの細かなポリシーはこのパッケージで扱っていません。必要であれば別途 CSP ミドルウェアを導入してください。
- HSTS を有効にする際は HTTPS を確実に提供していることを確認してください（誤った HSTS 設定はローカル環境でのテストを困難にします）。
- テストは `security_test.go` にあるため、CI での検証を推奨します。
