# `observability` パッケージ

概要: OpenTelemetry（OTel） 用の Echo ミドルウェアを提供します。アプリケーション名を付与した OTel のトレースミドルウェアを返します。

## 役割

`observability` は `otelecho.Middleware` をラップし、`ApplicationConfig` のアプリ名を渡して Echo 用のミドルウェアを生成します。これにより、リクエストごとのトレース生成とコンテキスト伝搬を容易に組み込めます。

主要ファイル:

- `observability.go` : `Middleware(appCfg *config.ApplicationConfig)` を提供し、`otelecho.Middleware(appCfg.Name())` を返します。
- `observability_test.go` : 挙動を検証する単体テスト。

## 必要度

### 本番運用での必須度

- 必須度: 本番運用で推奨

理由: 分散トレーシングによるパフォーマンス分析や障害解析は本番運用において重要です。OTel を用いたトレースは運用観点で有益ですが、導入の有無は組織のモニタリング体制に依存します。

### 開発/テスト運用での必須度

- 必須度: 開発/テスト運用で推奨

理由: 開発時にトレースを収集すると、サービス間の呼び出しや遅延の特定が容易になります。軽量に有効化しておくとデバッグに役立ちます。

### 無効化した場合の影響

ミドルウェアを適用しない場合、OTel による自動トレースが行われず、分散トレーシング情報が収集されません。ログやメトリクスのみでの対応となり、トラブルシュートの難易度が上がる可能性があります。

## 注意点

- OTel のエクスポーターやプロバイダの初期化はこのパッケージで行いません。アプリケーション起動時に適切な OTel プロバイダ（トレーサプロバイダ）とエクスポーターを初期化しておく必要があります。
- トレースに含めたくない機密情報がある場合は、Span 属性の取り扱いに注意してください。
