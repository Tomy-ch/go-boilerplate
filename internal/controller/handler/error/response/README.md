# response

このディレクトリは、HTTPエラーレスポンスの生成と管理を行います。

## 役割

- HTTPエラーのレスポンスを統一的に生成する機能を提供します。
- 他のハンドラやミドルウェアから利用されます。
- `gen/` サブディレクトリには自動生成された型定義が含まれます。
  - oapi仕様に基づく型定義が含まれ、APIのエラーレスポンスを一貫して処理を可能にします。
  - このエラーレスポンスを生成するために、openapi.yamlにはダミーのパス設定として`_internal/types/error-response`が設定されています。
    この設定により、API仕様に基づくエラーレスポンスの型が生成されます。

## エラーレスポンスの構造とJSON例

エラーレスポンスは、以下のような構造を持ちます。

### HTTPレスポンスのエラー時のJSON

```json
{
  "Code": "INTERNAL_ERROR",
  "Details": [
    "Detailed error message."
  ],
  "Message": "サーバーで予期しないエラーが発生しました。時間をおいて再度お試しください。",
  "RequestID": "123e4567-e89b-12d3-a456-426614174000",
}
```

このJSONは、HTTPエラーが発生した際にクライアントに返されるレスポンスの例です。

`Code` フィールドは、エラーの種類を示すコードです。

`Details` フィールドには、エラーの詳細情報が含まれます。

`Message` フィールドは、クライアントに表示されるメッセージで、ユーザーフレンドリーな内容になっています。

`RequestID` は、リクエストの識別子で、トラブルシューティングに役立ちます。

ステータスコード(`HTTPStatus`)やエラー(`Internal`)の情報は、内部ログで使用されますが、クライアントには返されません。

## 設定変更方法

- エラーレスポンスのロジックを変更する場合
  - 変更すべきファイル: `error_response.go`
- ステータスコードに対応するエラーコードやメッセージを変更する場合
  - `http_error.go` で定義されている、`const`のエラーコードやメッセージを変更します。

## 必要度

- 本番運用での必須度: 必須
- 無効化した場合の影響: エラーレスポンスが適切に生成されなくなり、クライアントに不適切なエラー情報が返される可能性があります。

## 代替手段

別の方法: 独自にエラーレスポンスを生成するコードを各ハンドラに実装する方法

- メリット: 柔軟性が高い
- デメリット: コードの重複が増え、保守性が低下

## 注意点

- よくある設定ミス: エラーコードやメッセージの不整合
- 環境依存の挙動: 特になし
