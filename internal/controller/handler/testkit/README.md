# `handlertest` パッケージ

## 概要

ハンドラ層（コントローラ）のテストを補助する小さなユーティリティ群の集合です。Echo を使ったルート/ハンドラのテストで共通して必要になるインスタンス生成、トレース注入、アサートヘルパーなどをまとめています。

このディレクトリ配下には、いくつかの細かいユーティリティがあり、それぞれ役割が分かれています。主なサブディレクトリと役割は以下の通りです。

- `testassert/`: レスポンスの JSON 等価検証や Echo ルート定義のアサーションを提供します（主に検証ロジック）。
- `testecho/`: HTTP リクエスト生成と Echo への実行を支援するビルダー（テストでのリクエスト作成を簡潔にするヘルパー）。
- `testinstance/`: `Echo` インスタンス、`gomock` コントローラ、テスト用ロガー/トレーサ等の共通テストインスタンスを生成するヘルパーを提供します。
- `testspan/`: テスト実行時に Echo のリクエストコンテキストへテスト用スパン（トレース）を埋め込み、終了処理を行うユーティリティを提供します。

## 推奨される利用方法（役割分担）

- ハンドラの単体テスト（UT）: `testinstance` で必要なモックやコンテキストを作り、`testecho` のビルダーでリクエストを組み、`testassert` でレスポンスを検証します。
- 結合的なルート検証: `testecho` の Serve 方式でルータ経由の代表ケースを実行し、`testassert` で結果を検証します。
- トレースの検証が必要な場合: `testspan` を使ってコンテキストにスパンを注入し、トレース情報を取り出してアサートします。

## 必須度/影響

- 本番運用: 不要（テスト補助ツールのため本番バイナリには含めない）
- 開発/テスト: 推奨（テストの信頼性と簡潔さを保つため、各プロジェクトのテストで利用してください）
- 無効化した場合: テストコードが冗長になりやすく、トレースやルート検証の再利用性が低下します。CI 安定性にも影響する可能性があります。

## テストと注意点

- 各ユーティリティはサブテストでの並列実行を念頭に置いて設計されています。`gomock` のコントローラや `echo.Echo` はサブテストごとに生成する運用を守ってください。
- トレース関連ユーティリティはグローバルトレーサの存在に依存する場合があります。より厳密に検証するには、テスト内で明示的にテスト用トレーサをセットアップしてください。
- 必要なら各サブディレクトリの README（`testassert/README.md`, `testecho/README.md`, `testinstance/README.md`, `testspan/README.md`）も参照してください。
