# internal/system

概要: アプリケーションのビルド情報やバージョン情報を管理するパッケージです。ビルド時に埋め込むメタ情報やランタイム出力用のバージョン文字列を提供します。

## 役割

- ビルド時に注入されるメタ情報（コミットハッシュ、ビルド日時、ビルドタグ等）を保持・提供する。
- アプリケーションの `--version` 出力や診断用エンドポイントで利用するバージョン情報の整形・取得を行う。
- テストでビルド情報のフォーマットや既定値を検証するためのユーティリティを提供する。

## 必要度

### 本番運用での必須度

- 必須度: 本番運用で推奨

理由: バージョン/ビルド情報は障害解析やデプロイ確認、サポート対応で重要です。必須ではない場合もありますが、運用性を高めるため導入を推奨します。

### 開発/テスト運用での必須度

- 必須度: 開発/テスト運用で推奨

理由: CI/CDやリリース管理でビルドメタ情報を埋め込むことで、どのアーティファクトがどのコミットに対応するかを正確に追跡できます。

### 無効化した場合の影響

- 実行バイナリにビルド情報が含まれなくなり、どのバージョンが稼働しているかの識別が困難になります。
- 障害発生時に該当コミットやビルドを特定できず、原因解析や再現が遅延する恐れがあります。

## 注意点

- **削除する場合**は、/docker/server/Dockerfile などのビルドプロセスからも関連設定を削除してください。
  - ARGのVERSION、REVISION、BUILD_DATEの指定を削除する必要があります。
  - RUN go build -mod=vendor -trimpath -ldflags "... の部分からも関連する -X オプションを削除してください。
    - VERSION、REVISION、BUILD_DATE に関する部分を削除します。
- ビルド情報にシークレットや機密情報を含めないでください（環境変数やトークンなど）。
- CI／Makefile 等で `ldflags` を使って正しく値を埋め込む仕組みを用意してください。
- バージョン表記のフォーマットはチームで合意しておくと運用上便利です（例: SemVer + コミット短SHA + ビルド日時）。
