# infrastructure/awsclient

[English](README.md) | 日本語

## 役割

本リポジトリの AWS SDK v2 アダプタ — 現在は SQS のキューアダプタと S3 のオブジェクトストレージ
アダプタ — が出発点にする `aws.Config` を組み立てます。両アダプタが個別に答えることになる 2 つの
判断をここが引き受けます。**資格情報をどこから取るか**と、**どの種類のリクエストがどの HTTP
クライアントを使うか**です。

## 資格情報: 選択肢ではなく 1 本の経路

`Resolve` は「static か chain か」のスイッチを提供しません。SDK 既定の credential chain は静的
資格情報を**自身の一部として含んで**います — 環境変数プロバイダは、共有プロファイル・web identity・
コンテナ / IMDS の各プロバイダと並ぶ chain の 1 リンクです。SDK 自身のモデルに static と chain の
分岐は存在しないため、判別子を足すことは標準が既に決着させた区別を再発明することになります。

したがって明示注入された資格情報は、chain の代替ではなく **chain の上書き**として扱います。

| `AccessKeyID` / `SecretAccessKey` | 挙動 |
| --- | --- |
| 両方あり | その静的資格情報で chain を上書きする |
| 両方空 | 既定の chain で解決する（IAM ロール・環境変数・共有プロファイル …） |
| 片方だけ | `ErrInvalidCredentials` で弾く |

片方だけの指定を弾くのは、どちらの意思表示とも読めないためであり、かつ SDK がアクセスキー ID と
空のシークレットでも平然と署名を作ってしまうためです。その場合、失敗は起動時ではなく最初の API
呼び出しで認証エラーとして表面化します。

## 起動時に落とす

`Resolve` は返す前に一度だけ資格情報を取得します。解決できない資格情報を持つデプロイは、最初の
呼び出しではなく起動時に落ちます。outbox publisher が endpoint を先んじて検証するのと同じ理由で、
起動してから publish が毎回失敗する relay は、試行回数を使い切ってメッセージを気付かれないまま
dead にしてしまいます。

これが、以前の「空の資格情報を弾く」検査を置き換えたものです。あの検査では誤設定と chain への
意図的な委譲を区別できませんでした。資格情報が**解決できるか**を問えば、その両方に一度で答えられます。

## HTTP クライアントが 2 つあるのは、守る対象が違うため

`Config` の `HTTPClient` は**サービス API の呼び出しにだけ**適用します。資格情報の解決は SDK 自身の
transport で動きます。

アプリの外向きクライアント（`observability.OutboundHTTPClient`）は link-local 宛てを無条件に拒否し、
クラウドメタデータへ向けた endpoint を dial の時点で止めます。しかし EC2 の IMDS
（`169.254.169.254`）と ECS の task metadata（`169.254.170.2`）は定義からして link-local です。
2 つの用途で 1 つのクライアントを共有すると、最も一般的なロール運用のデプロイだけが資格情報を
一切取得できなくなります。

守る対象が違います。ガードが存在するのは**外部サービスへの egress** を制約するためで、資格情報の
解決はプロセスが**自身の実行基盤**に対して自分は誰かを問い合わせる行為です。分けることで、
ガードは元々書かれた対象のトラフィックに掛かり続けます。

この適用外の範囲は metadata endpoint より広く、その点は明記しておく価値があります。**すべての**
資格情報解決リクエストが SDK のトランスポートで動きます — STS の web identity 交換（EKS IRSA）も
SSO のトークン交換も含みます。宛先 IP の検査も、ガードによる proxy の無効化（`Proxy = nil`）も、
それらには掛かりません。

これは見落としではなく意図した形で、塞ぐべき穴として残しているのでもありません。このトラフィックの
向き先を差し替える（`AWS_EC2_METADATA_SERVICE_ENDPOINT` / `AWS_CONTAINER_CREDENTIALS_FULL_URI` /
`HTTPS_PROXY`）にはプロセスの環境変数への書き込み権限が要り、それを持つ主体は資格情報そのものを
直接読めます。SDK 自身も、env で差し替えられる唯一の平文エンドポイントを loopback と既知の
ECS / EKS アドレスに制限しています。そもそも chain を覆うこともできません。コンテナ資格情報の
プロバイダは `LoadDefaultConfig` へ渡したクライアントを継承しないため、ガード付き transport は
IMDS・STS・SSO には届いてもその経路には届きません。

link-local を許す variant を退けた理由を含む判断の全文は
[ADR-0022](../../../docs/ja/adr/0022-egress-ssrf-guard.ja.md#aws-の-credential-chain-をガードする)
に記録しています。

## 注記

- `Region` は空にして SDK の解決（環境変数・共有プロファイル）へ委ねられます。上記のアダプタは
  いずれも自身が設定したリージョンを渡します。
- endpoint の上書きは各アダプタ側に残ります。サービス固有の関心であるためです
  （`sqs.Options.BaseEndpoint`、`s3.Options.BaseEndpoint` + `UsePathStyle`）。
