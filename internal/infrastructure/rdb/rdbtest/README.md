# internal/infrastructure/rdb/rdbtest

概要: データベース関連の統合テスト（実際のRDB接続を必要とするテスト）で使うテスト用ヘルパーをまとめたディレクトリです。Docker上のテストDBインスタンスの起動・接続や、テスト中のセットアップ／クリーンアップ処理を提供します。

## 役割

- テスト用のRDBインスタンス（Postgres 等）を簡単に立ち上げるユーティリティを提供する。
- テスト実行中に必要なマイグレーションやシードの適用、接続情報の管理を行う。
- テストケースから使える共通のセットアップ/ティアダウン関数を提供し、各テストでの重複実装を防ぐ。

## 必要度

### 本番運用での必須度

- 必須度: 不要

理由: 本番環境で実際に稼働するサービスにはテストユーティリティは含まれません。本ディレクトリはテスト・開発時の補助に限定されます。

### 開発/テスト運用での必須度

- 必須度: 開発/テスト運用で必須

理由: 実際のデータベースを用いた統合テスト（SQLクエリ・マイグレーション・リポジトリ層の検証など）を実行する場合、このディレクトリが提供するインスタンス起動・管理ロジックが必要です。CIでのテスト安定化にも役立ちます。

### 無効化した場合の影響

- 統合テストが実行できなくなるか、個別に環境を用意する必要が生じます。
- リポジトリやSQL周りの回帰を検出しにくくなり、テスト網羅性が低下します。

## 注意点

- Docker が利用前提の実装が含まれる場合、ローカルやCIで Docker デーモンが動作していることを確認してください。
- テスト実行前に必要なマイグレーションやシードファイルが正しく適用されるようにしてください（`database/migrations` や `seed` を参照）。
- 並列実行されるテスト（`go test -parallel`）では競合を避けるため、各テストで独立したデータベースを使うか、トランザクションでラップしてロールバックする等の工夫が必要です。
- テスト用の接続情報（ポート、ユーザ、パスワード）は環境変数またはテストヘルパーで安全に管理してください。誤って本番DBを上書きしないよう注意してください。
- テスト終了時は確実にインスタンスを停止・破棄すること（リソースリーク防止のため）。CI上でのタイムアウトや残存ボリュームによる影響を考慮してください。
