# RDB Driver

概要: RDB（例: PostgreSQL）への接続・トランザクション管理・ログラップを行うドライバ層のユーティリティ群です。アプリケーションからはこの層を通じて安全にDB操作を行います。

## 役割

- データベース接続（`sql.DB`）の初期化と設定管理を行う。
- トランザクションの開始・コミット・ロールバックを扱うユーティリティを提供する。
- DB操作に対するログ出力（クエリ、実行時間、エラー）をラップして提供する。
- テスト時に差し替え可能なプロバイダ/ドライバ抽象を提供し、単体テストの容易化を助ける。

## 必要度

### 本番運用での必須度

- 必須度: 本番運用で必須

理由: 本番環境では永続化層が動作しなければサービス全体が機能しないため、接続設定・トランザクション管理・適切なログ取得は必須です。

### 開発/テスト運用での必須度

- 必須度: 開発/テスト運用で必須

理由: 開発時やCIでのテストにおいて、トランザクションや接続周りの挙動を安定して扱うために本層が必要です。モックや差し替え実装も用意されているためテスト容易性が向上します。

### 無効化した場合の影響

- アプリケーションからDBへの接続が行えなくなり、永続化機能が停止します。
- トランザクション管理が適切に働かないため、データ不整合や部分的な書き込みが発生するリスクが高まります。
- DB操作ログが得られなくなり、障害時の原因調査が困難になります。

## 注意点

- 接続設定（最大接続数、接続タイムアウト、アイドル接続数など）は環境に応じて調整してください。
- トランザクション処理では早期にエラー検知してロールバックする実装を心がけてください。
- ロギングは本番環境での情報漏洩に注意し、センシティブなデータ（パスワード、トークン等）をログに含めないようにしてください。
- `DBTX` 等のインターフェイスを拡張する際は、生成コード（sqlc など）と互換性を保つよう注意してください。
- テスト用のモック/プロバイダ（`mock/`）を使うことで単体テストの副作用を避けられます。実際の統合テストでは `rdbtest` のユーティリティを併用してください。

## 参考ファイル

- `connection.go`: DB接続初期化と設定（接続文字列、最大接続数、接続ライフタイム等）を提供。
- `driver.go`: ドライバレイヤの主要インターフェイスと実装。
- `provider.go`: DIやプロバイダ向けのラッパー（アプリケーションでの注入点）。
- `transaction.go`: トランザクションユーティリティ（開始/コミット/ロールバック）の実装。
- `with_logging.go`: クエリ実行やトランザクション実行時のログラップ実装。

必要があれば、接続設定例や環境変数、サンプルの `go test` 実行方法を追記できます。
