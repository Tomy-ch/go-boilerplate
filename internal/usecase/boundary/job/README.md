# job サポートパッケージ

概要: `internal/usecase/interface/job` パッケージは、アプリケーション内で実行可能なジョブを定義・登録・実行するための抽象（`Job`）と実装（`Runner`）、およびテスト用のモックを提供します。ジョブは `Name()` と `Execute(ctx, args)` を実装することで登録可能です。

## 役割

- ジョブのインターフェース定義 (`Job`) と実行を管理する `Runner` の提供。

## 必要度

### 本番運用での必須度

- 必須度: 本番運用で必須

- 理由: バッチ処理や運用向けジョブを CLI から実行する機能がある場合、安定してジョブを登録・実行するための共通基盤として必須です。ただし、アプリケーションがジョブを一切使用しない場合は不要です。

### 開発/テスト運用での必須度

- 必須度: 開発/テスト運用で必須

- 理由: ジョブ実行ロジックの単体テストや統合テストでモックを利用して振る舞いを検証できるため、開発/テスト環境では重要です。

### 無効化した場合の影響

- ジョブの登録・実行や、CLI 経由でのジョブ実行が利用できなくなります。テスト用モックが無いとジョブ関連の単体テストが困難になります。

## 注意点

- `Run` は指定したジョブ名が存在しない場合にエラーを返し、エラーメッセージには利用可能なジョブ一覧を含むことを推奨します。
- ジョブの中断やタイムアウト制御は各ジョブ実装側で `context.Context` を受け取り協調的に行う必要があります。

## 実装の要点

- `Job` インターフェース:
  - `Name() string` と `Execute(ctx context.Context, args []string) error` を定義。
- `Runner` 実装（`runner`）:
  - `NewRunner(jobs []Job) (Runner, error)` はジョブ一覧から名前の重複をチェックして登録マップを構築する。
  - `Run(ctx, jobName, args)` は登録済みジョブを取得して実行する。見つからない場合は `unknown job` エラーを返す。
  - `Names()` は登録されているジョブ名をソートして返す。

## 使い方

- ジョブを実装する例:

```go
type MyJob struct{}
func (m *MyJob) Name() string { return "myjob" }
func (m *MyJob) Execute(ctx context.Context, args []string) error { /* 実行処理 */ }
```

## 前提 / 要件

- ジョブ実装は `context.Context` を尊重し、キャンセル/タイムアウトを正しく扱うことが望ましい。
- 重複名チェックを実装し、ジョブ名の一意性を保証することを推奨します。
