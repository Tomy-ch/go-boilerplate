# security

概要: このディレクトリは **HTTP レイヤーにおけるセキュリティ関連ミドルウェア**（CORS・セキュリティヘッダ・Cookie 設定など）を DI 経由で Echo に組み込むための fx モジュール群を提供します。
これらは controller 層のミドルウェアパイプラインに、統一的な Priority をもって適用されます。

## 役割

- CORS 設定の適用（AllowOrigins / AllowMethods / AllowHeaders 等）
- セキュリティヘッダの付与（HSTS / XSS-Protection / NoSniff 等）
- Cookie 設定および属性付与（Secure / HttpOnly / SameSite）

これらを **DI（Uber FX）経由でミドルウェアとして提供し、routing や handler から独立して管理**します。

## 必要度

### 本番運用での必須度

- 必須度: **本番運用で必須**

理由:

- CORS はブラウザ経由の外部アクセス制御に不可欠
- セキュリティヘッダは XSS・クリックジャッキング等の攻撃への防御に必要
- Cookie 属性 (Secure / HttpOnly / SameSite) は認証情報の保護に必須

**本番の API 保護において必須の機能群です。**

### 開発/テスト運用での必須度

- 必須度: **開発/テスト運用で推奨**

理由:

- CORS がないとローカルフロントエンド (Next.js 等) が API にアクセスできない
- セキュリティヘッダは本番用設定の検証として有効
- Cookie の挙動（SameSite / Secure 等）を早めに確認できる

※ 環境に応じて CORS 設定を緩めることは可能です。

### 無効化した場合の影響

- CORS 無効化 → フロントエンドから API にアクセスできなくなる可能性
- セキュリティヘッダ欠落 → XSS／クリックジャッキング等の攻撃リスク増大
- Cookie セキュリティ無効化 → セッションハイジャック・CSRF の危険性

特に **本番環境では絶対に無効化すべきではありません。**

## 注意点

- **Priority 順序**でミドルウェアが適用されるため、他のミドルウェアと競合しないよう固定値で管理しています。
- Cookie の Secure 属性は HTTPS 接続でのみ有効です（ローカルの http 環境では挙動が変わります）。
- CORS 設定は外部サービスとの連携状況によって変更が必要となるため、
  **SecurityConfig の更新時にはミドルウェア設定の見直しを推奨します。**
- セキュリティ関連ロジックは HTTP レイヤー専用であり、
  **domain や usecase に知識を漏らさないように設計されています。**
