# lifecycle パッケージ

English | [日本語](README.ja.md)

概要: アプリケーションの起動 / 停止時に実行するフック（Start/Stop）を登録するための DI 層です。`fx` の `Lifecycle` をラップした `Registrar` を提供し、アプリ全体のライフサイクルイベントの登録を容易にします。

## なぜ専用ディレクトリとして切り出しているのか？

`lifecycle/` が独立ディレクトリとして存在する理由は、**アプリケーション全体の起動・停止（Start/Stop）を統合的に扱うための“中立レイヤ”を設ける必要があるためです。**

通常、`fx.Lifecycle` は DI 内部で直接使われますが、そのまま利用すると以下の問題が発生します。

### 1. fx 依存がアプリ全体に漏れてしまう

`fx.Lifecycle` を直接使うと、  

- HTTP サーバ  
- Observability（TracerProvider, Exporter）  
- Metrics サーバ  
- Worker / Cron  
など **あらゆる層が fx に依存してしまう** ため、  
Onion Architecture / DDD の「外側の技術詳細を内側に持ち込まない」という原則に反します。

➡️ `lifecycle.Registrar` によって  
**fx 依存を di 層に閉じ込め、下位レイヤは Start/Stop という抽象のみを参照できる** ようになります。

### 2. Start/Stop 処理が各所に分散して管理が困難になる

`fx.Lifecycle.Append()` を各パッケージが勝手に呼び始めると、

- どこで何が起動し、  
- どこで何が停止するのか、  
- 順序がどうなっているのか  

が追いづらくなり、保守性が低下します。

➡️ `lifecycle/` に「Start/Stop の登録窓口」をまとめることで、  
**アプリ全体のライフサイクルが一元管理でき、見通しが格段に良くなります。**

### 3. 直接 fx を使うとテストが極端にしづらくなる

`fx.Lifecycle` の Hook 登録は DI 前提のコードであり、  
`domain` や `usecase` などのテストでは不要かつ扱いづらい依存です。

`Registrar` に抽象化することで、

- テストでは Noop のスタブを渡せる  
- Hook を発火させたい場合だけ fx.App.Start/Stop を使う  

など **テスト容易性が大幅に向上します**。

### 4. Start/Stop は Echo に限らず “アプリ全体の概念”

ライフサイクルにぶら下がる処理は HTTP サーバ以外にも多数あります。

- トレーサー初期化 / シャットダウン  
- メトリクスエクスポータ  
- DB コネクションのクローズ  
- Queue コンシューマ  
- Cron / Worker  
- キャッシュクライアントの初期化  

これらを `server/` や `controller/` にまとめるのは責務違反です。

➡️ **アプリ全体のライフサイクル管理という横断 concern として独立させるのが自然** であり、  
その実装点として `lifecycle/` を切り出しています。

### 5. DI 全体の統制点として必要

`lifecycle.Module()` を見るだけで、

- Start/Stop の仕組みがどこで提供されているか  
- fx とアプリの境界線がどこにあるか  

が一目で分かるようになります。

➡️ DI の構造や依存グラフの解読が容易になり、チーム開発での安全性が高まります。

## 役割

- **ライフサイクル管理**: サービスの起動・終了時に実行すべき処理（サーバ起動、リソース解放など）を登録する抽象化レイヤを提供します。

## 必要度

- **本番運用での必須度**: 本番運用で必須。
  - 理由: 正常なシャットダウンや初期化処理を確実に行うため、Start/Stop フックの登録は本番環境で必須です。
- **開発/テスト運用での必須度**: 開発/テスト運用で推奨。
  - 理由: テスト環境でも起動・停止のフックが適切に動作することを確認することで、リソースのリークや順序依存の不具合を防げます。

### 無効化した場合の影響

- `Registrar` を提供しない／無効にすると、アプリ起動時の初期化処理や停止時のクリーンアップが実行されなくなり、リソースリークや不整合を招く可能性があります。

## 注意点

- `fx` の `Lifecycle` に依存しているため、`fx.App` のライフサイクルで正しく Start/Stop が呼ばれる前提の実装になっています。
- テスト内でフックの実行を検証する場合は `fx.App` を Start/Stop してフックを発火させる必要があります（パッケージ内のテストがその例です）。

## 参考ファイル

- `lifecycle.go` — `Registrar` インターフェースと `NewLifecycleRegistrar` の実装。`RegisterStart` / `RegisterShutdown` を公開し、`fx.Lifecycle.Append` で Hook を登録します。
- `lifecycle_di.go` — `Module()` を返すファイル。`fx.Module("lifecycle.registrar", fx.Provide(NewLifecycleRegistrar))` によって DI コンテキストに `Registrar` を登録します。
