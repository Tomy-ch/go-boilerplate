# ADR-0014: バンドル済み openapi.gen.yaml をコミット済みのクロスリポジトリ契約アーティファクトとして保持する

English canonical: [0014-retain-generated-openapi.md](../../adr/0014-retain-generated-openapi.md)

## ステータス

accepted

## 背景

ADR-0012（Redocly モジュラー仕様パイプライン）は **Lint → Bundle → Generate** という
3 段階のパイプラインを確立している。バンドルステップは `openapi/openapi.gen.yaml` —
すべての `$ref` が解決された単一ファイルの OpenAPI ドキュメント — を生成する。
サーバー側の観点では、このファイルは直後に oapi-codegen（ADR-0013、oapi-codegen
strict-server）が消費し、Go スタブ生成後は他の中間ビルドアーティファクトと同様に
破棄することが原理的には可能である。

しかし `openapi.gen.yaml` は、**Redocly ツールチェーンをインストールせずに外部コンシューマーが
解析できる唯一の完全解決済み契約の表現**でもある。フロントエンドのコードベースは別リポジトリで
このファイルを使って型付き HTTP クライアントコードを生成する（例: orval + zod）。
このファイルをコミットしない場合、フロントエンドは Redocly バンドルステップを自前で再現するか、
未解決のマルチファイル仕様を消費するかのいずれかを強いられ、どちらもリポジトリ境界を越えた
ツールチェーン結合とビルド複雑性を増大させる。

プロジェクト全体のルール（「生成ファイルをコミットしない」）は、古くなった出力が
暗黙的に信頼されることを防ぐために存在する。この緊張関係は、生成アーティファクトの
ドリフトゲート（ADR-0085、generated-artifact drift gate）によって解消される。
このゲートは、コミット済みの `openapi.gen.yaml` が現在のソースから乖離している場合に
PR を失敗させ、ファイルを常に最新の状態に保つ。

## 決定

`openapi/openapi.gen.yaml` を**コミット済みアーティファクト**としてリポジトリに保持する。

このファイルは `make gen-api`（`gen-bundle-oapi` ステップが
`redocly bundle openapi/openapi.yaml -o openapi/openapi.gen.yaml` を実行する）
によって再生成され、その鮮度は生成アーティファクトのドリフトゲート（ADR-0085）で
定義された `gen-oapi-artifacts-check` CI ワークフローによって強制される。
フロントエンドは GitHub API 経由（例: `gh` CLI）でコミット済みファイルを取得し、
Redocly ツールチェーンをインストールすることなく、自前のコード生成パイプライン
（例: orval + zod）のソースとして使用する。

このファイルは手動で編集してはならない。その作成ソースは `openapi/` 配下の
モジュラー仕様である（ADR-0012、Redocly モジュラー仕様パイプライン）。

## 影響

### ポジティブな影響

- フロントエンドは Node.js や Redocly をインストールすることなく、GitHub API 経由で
  任意の git ref から解決済み仕様を取得でき、フロントエンドのビルド依存関係を軽量に保てる。
- 単一ファイル表現は、追加の解決ステップなしに、標準的な OpenAPI ツール
  （orval、openapi-typescript、swagger-codegen など）で即座に解析可能である。
- コミット済みファイルは監査可能なスナップショットとして機能し、レビュアーは
  git 履歴のどの時点においても公開された契約の状態を確認できる。
- ドリフトゲート（ADR-0085）により、コミット済みファイルはモジュラーソースと
  常に同期が保たれる — 生成ファイルのコミットを通常躊躇させる「古くなったコミット済み出力」
  のリスクは CI によって機械的に排除される。

### ネガティブな影響

- OpenAPI ソースを変更するたびにコミット前に `make gen-api` ステップが必要であり、
  忘れると CI のドリフトゲートが失敗する。コントリビューターへの必須の規律ステップが増える。
- コミット済みファイルはモジュラーソースより大きく、リポジトリサイズを増大させ、
  多くのスキーマファイルを変更する PR でノイズの多い差分を生成する。
- `openapi.gen.yaml` の手動編集は禁止されているが、リポジトリのツールで技術的には
  ブロックされていない。コントリビューターはこの制約をコンベンションとして認識する必要がある。

## 検討した代替案

### 生成後に破棄する; フロントエンドがバンドルステップを再現する

フロントエンドの CI が Redocly をインストールし、モジュラーソース（サブモジュールとして
チェックアウト、または API 経由で取得）に対して `redocly bundle` を実行する。
却下: フロントエンドに Redocly ツールチェーンをビルド依存関係として強いられ、
サーバーのモジュラーな `$ref` 構造を理解する必要が生じる — リポジトリ境界を越えた
密結合になる。

### GitHub Releases またはパッケージ経由で公開する

バンドルされた YAML を各リリースで GitHub Release に添付するか、パッケージアーティファクトとして
公開する。却下: 日常的な開発フローでは、フロントエンドはマージされた PR ごとではなく
リリースのケイデンスでのみ更新を受け取ることになる。スプリント中盤の API 変更は
リリースが切られるまでフロントエンド開発者から見えなくなる。

### 実行中のサーバーエンドポイントから仕様を提供する

サーバーがランタイムエンドポイント（例: `/openapi.yaml`）で解決済み仕様を公開し、
フロントエンドがデプロイ済みの環境から取得する。却下: フロントエンドのビルドパイプラインに
環境依存関係が導入され、仕様へのアクセスが動作中のサーバーの存在に依存してしまう。

## 補足

- `openapi/openapi.gen.yaml` はコミット済みであることを確認済み（git ツリーに存在、
  .gitignore に記載なし）。
- ビルドターゲット: `.makefiles/openapi/gen.mk`（`gen-bundle-oapi-ci` が
  `redocly bundle openapi/openapi.yaml -o openapi/openapi.gen.yaml` を実行する）。
- 鮮度の強制: ADR-0085（generated-artifact drift gate）、CI ワークフロー
  `gen-oapi-artifacts-check`。
- クライアント側の使用パターン（orval + zod）: `openapi/boundary-ownership.md` 参照。
- 関連: ADR-0011（OpenAPI ファースト）— 仕様をワイヤー契約の真実のソースとする根本的な決定。
- 関連: ADR-0012（Redocly モジュラー仕様パイプライン）— このファイルを生成するバンドルステップ。
- 関連: ADR-0013（oapi-codegen strict-server）— このファイルのサーバー側コンシューマー。
- 関連: ADR-0085（generated-artifact drift gate）— このコミット済みアーティファクトを
  最新に保つ CI の仕組み。
