# ADR-0007: AI協働開発 — AGENTS.md を運用契約とする

English canonical: [0007-agents-md-operational-contract.md](../../adr/0007-agents-md-operational-contract.md)

## ステータス

accepted

## 背景

このリポジトリは AI 支援開発ツール（Claude Code、Cursor、GitHub Copilot、Gemini CLI / Code Assist、OpenAI Codex CLI）と安全に連携して動作するよう設計されている。各ツールはそれぞれ固有の設定機構（`.claude/`、`.cursor/`、`.github/copilot-instructions.md`、`.gemini/`、`.agents/`）を持つことを想定されているが、共通の契約がなければ、各設定が同じ行動規則（変更スコープ、禁止ショートカット、レイヤー境界規則、git 規律、言語要件）を独立して再定義することになり、ツール間でのドリフトリスクが生じる。

このコードベース上で動作する AI エージェントは、どのツールやモデルが稼働中であるかにかかわらず一貫して制約されなければならない。

- エージェントはレイヤー境界を侵してはならない（人間の開発者と同じ規則。CI によって [ADR-0006](0006-structural-safety-via-tooling.ja.md) に従い強制される）。
- エージェントは生成ファイルや保護された設定を変更してはならない。
- エージェントは保護されたブランチに直接コミットしてはならない。
- エージェントは指示なしに新しいアーキテクチャパターンを導入してはならない。
- エージェントは OpenAPI ファースト フローに従わなければならない（ADR-0009 参照）。

アーキテクチャの構造的安全性（ADR-0006）はビルドレイヤーで違反を処理するが、行動上の制約——エージェントが触れてよいもの、タスクの前後にどう振る舞うべきか——はリンターで表現できない。これらはエージェントのハーネスがセッション開始時に読み込む宣言的な契約を必要とする。

副次的な懸念として指示の優先順位がある。エージェントがアーキテクチャドキュメント、ルールドキュメント、アドホックなユーザー指示から相反するガイダンスを受け取った場合、解決順序を明示しなければならない。

## 決定

`AGENTS.md`（プロジェクトルート）を、このリポジトリと連携する AI エージェントの**唯一の運用契約**として確立する。優先順位は `AGENTS.md` → `docs/rules.md` → `docs/architecture.md` → ユーザー指示の順となる。`AGENTS.md` は**人間のみが保守**する——AI エージェントはこれを変更してはならない。

契約がカバーする内容：

- 指示の優先順位。
- 正典ドキュメントマップ（コードを変更する前に読むべきもの）。
- 変更スコープのハード制約（エージェントが触れてよいディレクトリ）。
- 禁止ショートカット（生成ファイル、保護ブランチ、レイヤーバイパス）。
- AI ツール設定ディレクトリ（エージェントのスコープ外として宣言）。
- スキル実行例外（明示的なスキル呼び出し中のスコープ緩和。スキル固有の `SKILL.md` とハード保護ファイルで制限）。
- Git 規則（ブランチ命名、コミット規約、PR 修正後の自動プッシュ禁止）。
- 言語規則（ユーザーが英語を要求しない限り、表示出力はすべて日本語）。

ツールごとのハーネスファイル（`.claude/settings.json`、`.cursor/rules/` 等）は各ツールのネイティブ機構に対して契約を翻訳・拡張するが、`AGENTS.md` が真実のソースであり続ける。再利用可能なエージェント手順（scaffold、review、commit、release-notes 等）は `.claude/skills/` 配下のスキルファイルとして体系化する。

## 影響

### ポジティブな影響

- 人間がレビューした単一のドキュメントがリポジトリ内のすべてのツールにわたる AI ツールの動作を管理する。ツールごとの設定ドリフトが低減される。
- 指示の優先順位が明示される。競合が決定論的に解決される。
- 保護ファイル（生成コード、ポータルコンテンツ、`AGENTS.md` 自体）が列挙され、意図しない上書きのリスクが低減される。
- `.claude/skills/` 配下のスキルファイルが、基本契約を変更することなく再利用可能な手順を体系化する。
- `AGENTS.md` と正典 README に基づく契約は、AI の出力誤差を収束させる効果もある。開発者が正典 README を読んで作業した場合と同等のレベルに AI の出力品質を引き上げる。

### ネガティブな影響

- `AGENTS.md` はアーキテクチャの進化に合わせて人間が最新状態に保つ必要がある。古い契約はエージェントを誤解させる。
- AI ツールによって準拠の忠実度は異なる。契約はベストエフォート機構であり、ハード強制層ではない（構造的強制は CI が担う）。
- `.claude/skills/` 配下のスキルファイルはコードベースの成熟とともに増加し、独自のメンテナンス規律を要求する。

## 検討した代替案

### ツールごとの設定のみ

各 AI ツールのネイティブ設定ファイルを、そのツールの唯一の契約とする。却下：ツール間でルールが乖離し、共通のアーキテクチャ制約を複数箇所で再定義・維持しなければならなくなる。

### docs/rules.md に AI ルールをインライン化

エージェントの行動規則をアーキテクチャルールドキュメントにマージする。却下：`docs/rules.md` は人間の開発者向けのアーキテクチャドキュメントであり、エージェント固有の行動制約（変更スコープ、禁止ショートカット、git 規律）を混在させるとどちらの読者にとっても明確さが損なわれる。

## 補足

- ソース: `AGENTS.md`（全文——運用契約本体）。
- スキルファイル: `.claude/skills/`（契約を拡張する手順ごとのエージェント機能）。
- 関連する構造的強制: [ADR-0006](0006-structural-safety-via-tooling.ja.md)。
- 関連: `docs/architecture.md` § "AI-assisted Development"。
