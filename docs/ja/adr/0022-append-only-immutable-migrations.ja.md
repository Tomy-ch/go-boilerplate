# ADR-0022: マイグレーションを追記専用かつイミュータブルとして扱う

English canonical: [0022-append-only-immutable-migrations.md](../../adr/0022-append-only-immutable-migrations.md)

## ステータス

accepted

## 背景

データベースマイグレーションはスキーマ変更の完全な履歴を記録する。プロジェクトはgolang-migrateを使用しており、これはマイグレーションファイルを順番に適用し、チェックサムによる改ざん検出が可能である。あるマイグレーションファイルが環境に適用済みの状態で変更されると、golang-migrateはハッシュの不一致を報告し処理を拒否し、元のファイルを以前に実行したすべての環境が壊れる。

ツールによる強制の観点を超えて、適用済みマイグレーションを変更することは監査証跡を破壊し、任意の過去バージョンのスキーマを再現することを不可能にする。これはインシデントのデバッグ・既知の状態へのロールバック・新規環境のゼロからの構築において重要な性質である。

## 決定

`database/migrations/`配下のすべてのマイグレーションファイルは**追記専用かつイミュータブル**である。ファイルが一度コミットされたら決して変更してはならない。修正・カラム名変更・制約の変更を含むすべてのスキーマ変更は新しいマイグレーションファイルとして表現しなければならない。権威ある規則と根拠は[`docs/rules.md`](../../rules.md)の§ "Database Migration"を参照。

## 影響

### ポジティブな影響

- 任意の時点のスキーマはマイグレーションシーケンスを最初から再生することで再現可能である。
- golang-migrateのハッシュ検証が偶発的な編集に対する自動整合性チェックを提供する。
- すべての環境（ローカル・CI・ステージング・本番）が同一のマイグレーションシーケンスを実行し、環境固有のスキーマドリフトを排除する。

### ネガティブな影響

- 適用済みマイグレーションの誤りを修正するには、些細な修正（例：スペルミスのコメント）でも新しい前方マイグレーションを追加する必要がある。
- マイグレーションシーケンスは単調に増加し、圧縮やスカッシュのステップはない。

## 検討した代替案

### 適用済みマイグレーションの編集を許可する

インライン修正が可能になるが、golang-migrateのハッシュ検証を無効化する。元のファイルをすでに適用した環境は無言で壊れるか次回実行時に失敗する。整合性の保証は利便性よりも価値が高いため却下。

### マイグレーションのスカッシュ

適用済みマイグレーションをすべてベースラインスキーマファイルに定期的に圧縮する。ファイル数は減るが個々のステップを再生する能力を失う。ベースラインからブートストラップした新環境は特定の歴史的バージョンに向かってロールフォワードできなくなる。現在のプロジェクトライフサイクルでは対象外。
