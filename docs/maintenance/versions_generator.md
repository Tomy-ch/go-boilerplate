# Versions Generator — Maintenance Guide

This document explains what must be done **after adding a new generator tool** to the Tools containers (`go_tool_runner` / `node_tool_runner`).

Generated artifacts in this repository are validated in CI by **GeneratedArtifactsCheck**.  
The check automatically determines whether a change in generated files is caused by:

- a **generator tool version change**, or
- a **missing regeneration step**.

To make this possible, the versions of generator tools are tracked as a manifest.

Therefore, **when adding a new tool, the following steps are required.**

## 1. Add version extraction logic to `scripts/gen_tools_version.sh`

After adding a new tool, you must update the script that outputs generator versions.

Example (when adding a Go-based tool):

```sh
go_section() {
  echo "## Go-based tools (go_tool_runner)"
  echo "- golang-migrate: $(normalize \"$(migrate -version 2>&1 || echo 'unknown')\")"
  echo "- mockgen: $(normalize \"$(mockgen -version 2>&1 || echo 'unknown')\")"
  echo "- oapi-codegen: $(normalize \"$(oapi-codegen --version 2>&1 || echo 'unknown')\")"
  echo "- sqlc: $(normalize \"$(sqlc version 2>&1 || echo 'unknown')\")"

# ★ Add your new tool here

  echo "- your-tool: $(normalize \"$(<tool-command> <version-command> 2>&1 || echo 'unknown')\")"
}
```

If the tool belongs to the Node toolchain, add it inside `node_section()` instead.

## 2. Run `make gen-tools-meta` to update version metadata

Run the following command locally:

```bash
make gen-tools-meta
```

This updates the generator version manifest:

```text
docs/meta/generator-versions.txt
```

The file records the versions of all generator tools currently used.

## 3. Commit the updated artifacts

After adding a new tool, you **must commit** the following:

- `docs/meta/generator-versions.txt`
- any regenerated artifacts (`make gen` output)

CI relies on this file to determine whether generated-file changes are valid.

## 4. Ensure the CI artifact check passes

When you create a PR, the GitHub Actions workflow:

```text
.github/workflows/gen-artifacts-check.yaml
```

will execute the following checks:

1. Detect differences in generated artifacts  
2. Compare them with the recorded generator versions  
3. Comment on the PR if the change is caused by a generator update  
4. Fail CI if a mismatch remains

After adding a new tool, always verify that this CI workflow passes.

## Why is this necessary?

This project contains many generated artifacts, such as:

- Go code generated by **oapi-codegen**
- Query/Model code generated by **sqlc**
- Mocks generated by **mockgen**
- Bundled OpenAPI files generated by **swagger-cli**
- HTML documentation generated by **redocly**
- and others

These artifacts are **strongly dependent on the generator tool versions**.

Without version tracking, the following problems often occur:

- A developer generates files using an **older local tool**
- CI runs with a **newer tool version**
- Generated artifacts change unexpectedly
- Pull requests become noisy and unstable

To prevent this, the project stores generator tool versions as a **manifest** and keeps them synchronized with CI.

This allows the CI system to determine whether a diff in generated files is caused by:

- an intentional tool upgrade, or
- a missing regeneration step.

## Summary: Required steps when adding a new tool

|Task|Required|Description|
|---|---|---|
|Add entry in `scripts/gen_tools_version.sh`|Required|Expose the tool version|
|Run `make gen-tools-meta`|Required|Update version manifest|
|Commit manifest and generated artifacts|Required|Synchronize with CI|
|Run `make gen` if artifacts are affected|Required when applicable|Regenerate affected files|
|Add tool to docker-compose|If necessary|When a new service/container is required|

## Closing Notes

As the number of generator tools increases, the risk of environment-related differences also increases.

This **manifest-based approach** minimizes those inconsistencies and ensures:

- clean pull requests
- stable CI pipelines
- reproducible development environments

Whenever a new generator tool is added, please follow the steps in this guide.
