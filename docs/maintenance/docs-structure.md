# Documentation Structure Rules

This project uses an **automatically generated documentation portal**.

The portal (`docs/portal`) reads `docs.json`.  
This file is generated by the following script.

```txt
scripts/portal/gen-docs-json.ts
```

To ensure this generation process works correctly, the following rules must be followed.

## 1. Root Documents

English documentation is placed in the following location.

```txt
docs/
```

Example:

```txt
docs/
├ architecture.md
├ development-flow.md
├ decisions.md   # redirect stub → adr/
├ rules.md
├ adr/    # Architecture Decision Records (per-file ADR)
└ reference/dependencies.md
```

These files are displayed in the **Architecture (English)** section.

## 2. Japanese Documents

A Japanese document sits **beside its English canonical**, named `<name>.ja.md`. The suffix is what
separates the languages; there is no separate directory, and the generator splits them by suffix.

These files are displayed in the **Architecture (Japanese)** section.

## 3. Section Documents

If a subdirectory is created, a documentation section is automatically generated.

Example:

```txt
docs/project
docs/maintenance
```

Markdown files within the directory are treated as pages.

Example:

```txt
docs/project
├ policy.md
├ scope.md
└ versioning.md
```

Generated section:

```txt
Project (English)
```

## 4. Japanese Section Documents

A section's Japanese documents live in that same section directory, as `<name>.ja.md`. Nothing else
is needed — the generator finds them by suffix and files them under:

```txt
Project (Japanese)
```

## 5. Reserved Directories

The generator treats only this one as a non-section:

```txt
docs/portal
```

`docs/openapi`, `docs/coverage`, `docs/db-schema` and `docs/godoc` are scanned as ordinary
sections and surface as quick links through `meta.reference_links` — see
[`portal-manifest.md`](portal-manifest.md), which is the reference for that contract.

## 6. Portal Related Files

The following files are automatically generated and must not be edited manually.

```txt
docs/portal/docs.json
```

To regenerate:

```txt
make gen-docs-json
```

## 7. Adding a New Documentation Section

When adding a new section:

```txt
docs/security
```

Example:

```txt
docs/security/auth.md
docs/security/auth.ja.md
```

The portal will automatically add the following.

```txt
Security (English)
Security (Japanese)
```

## 8. CI Integration

The documentation portal is automatically updated by CI.

```sh
make gen-docs-json
```

## Summary

|配置場所|言語|
|--------|--------|
|docs/*.md|English|
|docs/*.ja.md|Japanese|
|docs/<section>/*.md|English セクション|
|docs/<section>/*.ja.md|Japanese セクション|

By following these rules, the documentation portal can be maintained with a consistent structure.
