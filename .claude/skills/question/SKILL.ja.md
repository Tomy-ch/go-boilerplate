# Question

問い手が実際に何を意味していたのかを割り出し、それを確認し、答えを所有する相手へ問いを渡す。

## 使うとき

- 問いが 2 通り以上に読めるとき。
- 問い手がどのスキルが何を扱うのか分からない、あるいはどこへ持って行くべきか尋ねたとき。
- 前の実行が誤った読みで答えてしまい、振り直しが要るとき。

読みが既に一意なら使わない —— 所有スキルへ直接行く。そして自分で答え・手順・比較・レビューを出すために使ってはならない。

## 契約

| | |
| --- | --- |
| **所管** | 問いの意味論的解釈（世界 / 意図 / 対象の 3 軸）、人間への確認、所有スキルへの引き渡し |
| **しないこと** | 自分で答える / 手順を組む / 比較する / レビューする / 軸が割れているのに黙って片方を選ぶ |
| **開始条件** | 問いの読み方が一意でないとき、どのスキルが担当か分からないとき |
| **停止条件** | 引き渡し先が決まったとき、または該当するスキルが無いと分かったとき |

## なぜ必要か

ここにある他のスキルはどれも、誤発火した問いを振り直す door check を持っている。あれが拾うのは簡単な側 ——
内側から見て誤った入口が*見える*場合。このスキルが引き受けるのはそちらではない。2 通りの読みのどちらでも
問いとして正しく成立し、どちらの行き先も有能で自信のある、しかし範囲の違う答えを返し、そして出力の中に
もう一方の読みが存在したことを示すものが何も無い —— そういう場合である。

一番よくある形は裸の「今」。外の世界を指すこともあれば、今あるこのリポジトリを指すことも、この窓の差分を
指すこともある。読みごとに所有者が違い、どの所有者も有能に答え、文だけでは選べない。片方を選んだスキルは
完結して見える答えを出す —— だからこそ選ぶのが誤りで、聞くのが正しい。

**曖昧さは問い手の中にあるので、問い手が解く。** これは弱いヒューリスティックの逃げ道ではなく、情報が実際に
在る場所である。`AGENTS.md` が設計・方針の決定を人間のゲートに置いているのも同じ理由で、問いを黙って
組み替えるルーティングの決定はその 1 つにあたる。

## 3 つの軸

問いをこの軸で解く。ほとんどの問いは 3 軸とも一意で、ここに届くものは 1 つ、たまに 2 つで割れる。

| 軸 | 分岐 | 割れているサイン |
| --- | --- | --- |
| **世界** | 外の世界 / このリポジトリ全体 / この窓の差分 | 裸の「今」「最近」「普通」、あるいは基準を述べない比較 |
| **意図** | 症状 / 目標 / 知識 / 未決の選択 | 動作も失敗も名指さない「どう」「大丈夫」「どうなってる」 |
| **対象** | 実装 / テスト / コメント / ドキュメント / 語彙 / 運用 | それら全部を一度に指す名詞（「品質」「これ」「この機能」） |

軸は互いに独立なので、スキル名へ飛ばずに軸ごとの読みを別々に述べる。読者は「`arch-check` ではなく
`impl-review`」より「差分ではなくリポジトリ全体の話」のほうがはるかに訂正しやすい。前者は自分の問いに
ついての話だが、後者は相手が知らないかもしれない道具についての話だからである。

## Step 1 — 問いを読み、解ける分を解く

問いを 1 行で言い直し、軸ごとの読みを添える。文が実際に決めている軸はすべて解く —— たいていは全部決まる。

これは文とその文脈から行い、コードベースを読んで行わない。曖昧さを解くために調査するのは行き先の仕事であり、
しかもたいてい徒労に終わる。問い手がどの「今」を意味したかを書いてあるファイルは存在しない。

軸を正当に決められる文脈上の事実は 2 つで、使ったときはどちらも明示する:

- **開いている差分。** ブランチに未マージのコミットがあれば「この窓」の読みが生きており、clean tree なら
  ほぼあり得ない。確認して、何が分かったかを述べる。
- **直前の会話。** レビューの後に続く問いは、たいていその変更についてである。文脈から推測したと述べ、
  訂正できるようにする。

## Step 2 — 聞く。ただし実際に割れている軸だけ

全軸が解けたなら Step 3 へ飛び、読みを 1 行で述べる。一意な問いに対してモーダルを作らないこと。稀なケースの
ために、その摩擦を普通のケースが払うことになる。

軸が本当に割れているときは `AskUserQuestion` を呼ぶ —— 割れた軸 1 つにつき 1 問、最大 2 問。選択肢は
**その人の問いの読み方**として書き、スキル名では書かない:

```text
質問: 「今」はどの範囲を指していますか？
選択肢:
  - 外の世界と比べて — 一般的なやり方として今も妥当か
  - このリポジトリ全体 — コードベース全体が筋の通った状態か
  - この窓の変更 — いま書いた差分がどうか
  - どれでもない — 別の意味だった
```

「どれでもない」を必ず入れる。自分の 3 つの読みしか出さないルーターは、どれも正しくなくてもそのうち 1 つを
回収してしまう。

## Step 3 — 行き先を実行時に解決する

**ルーティング表を焼き込まないこと。** スキルは追加され、改名され、退役する。このファイルに書いた表は静かに
drift する —— もう存在しないスキルへ振ったり、いま答えを所有しているスキルを取りこぼしたりする。代わりに
インストール済みの集合を読む:

```bash
ls .claude/skills/
head -20 .claude/skills/*/SKILL.md      # frontmatter: name + description + argument-hint
```

各スキルの `description` は所管を述べ、末尾で明示的に所管*しない*ものを述べる。その `Do NOT use it for…`
節が frontmatter の中で最も信頼できるルーティング信号である。境界を所有した本人が書いているからである。
いくつかのスキルは Owns / Never / Starts when / Stops when を並べた `## Contract` 表も持つので、description
だけでは際どいときはそれを読む。

解決した読みを問いと一緒に渡し、読みが行き先の引数を決めるならそれも渡す —— 「そもそも存在するのか」を
知りたいなら `repo-truth --depth=full`、「そもそも開いた問いなのか」を聞いているなら
`research --stage=dissolve`、操作ではなく手順が欲しかったなら `how-to --mode=lookup`。

インストール済みのどのスキルもその問いを所有していないなら、はっきりそう述べて止まる。それは findings ——
スキル集合の穴 —— であって、ここで答える理由ではない。

## Step 4 — 引き渡す

行き先と理由を 1 行で述べ、起動する。ユーザーは既に読みを承認しているので、スキル選択を再確認するのは
たった今下した決定に 2 つ目のゲートを置くことになる。

```text
「この窓の変更」の読みで受け取りました。差分のドメインモデリングは /impl-review が所有します。
```

引き渡しがこのスキルの唯一の出力である。行き先が何を見つけるかを要約しない。一部を先回りして答えない。
2 つの行き先を回して比べない —— 3 つ目は徹底ではなく、読みの問いを未解決のまま放置したということである。

## 引数

| 引数 | 効果 |
| --- | --- |
| `--to=<skill>` | 呼び出し側が行き先を既に知っている。Step 1-3 を飛ばして引き渡す |
| `--explain` | 軸の解決と行き先を示し、起動せずに止まる |

`--explain` は「これはどこへ行く問いか」のためのモード —— リポジトリではなくスキル集合についての問いである。
腑に落ちなかったルーティング判断を検分するのにも使う。

## チェーンではない

ルーティングはチェーンの逆であり、違いは決定がどこに座っているかにある。他スキルへチェーンするスキルは
ユーザーの代わりに決める。こちらはその決定をユーザーの前に置いて、そのうえで実行するために存在する。軸が
割れているときの確認が省略可能でない理由も、行き先を 2 度起動しない理由もそこにある。

同時に、行き先は独立に起動可能なままである。このスキルが必須の入口になるわけではない —— 範囲の明確な問いは
所有者へ直接行くべきで、こちらはそうでないものを引き受ける。

## やること / やらないこと

- ✅ 文が決めている軸はすべて解く。本当に割れている軸だけ聞く。
- ✅ 選択肢は問いの読み方として書く。スキル名では書かない。
- ✅ 「どれでもない」を必ず出す。
- ✅ 行き先はインストール済みスキルの frontmatter を実行時に読んで解決する。
- ✅ 解決した読みと、行き先の引数を問いと一緒に渡す。
- ✅ 開いている差分や直前の会話が軸を決めたなら、そう述べる。
- ✅ 「どのスキルも所有していない」は findings として報告して止まる。
- ✅ 日本語で応答する。
- ❌ 問いに答える、手順を組む、選択肢を比較する、何かをレビューする。
- ❌ 軸が割れているのに読みを選ぶ。
- ❌ ルーティング表を焼き込む、インストール確認をせずにスキルへ振る。
- ❌ 曖昧さを解くためにコードベースを読む —— 曖昧さはファイルではなく問い手の中にある。
- ❌ 一意な問いに対してモーダルを出す。
- ❌ 両方の読みを覆うために 2 つの行き先を起動する。
